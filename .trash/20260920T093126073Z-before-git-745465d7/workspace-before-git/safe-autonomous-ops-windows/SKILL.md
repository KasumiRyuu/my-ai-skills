# Windows 自主安全操作（Safe Autonomous Ops）

## 核心目标

在已授权的 Windows 项目工作区内自主完成常规操作，并在丢弃或覆盖原内容前建立可验证的
回滚点。遵循“限定工作区、显式启用、先备份再操作”的原则，使用 PowerShell 原生
命令与 Windows 路径规则。

通过 SSH 操作 Linux/POSIX 服务器时，直接遵循本文件“SSH 远程 Linux 操作”一节，
在远端工作区建立回滚点。本机与远端分别检查，不能以一侧的授权或备份代替另一侧。

## 判定执行位置

- **Windows 本机。** 本地文件、脚本和 Git 操作使用本文件及 PowerShell 参考资料。
- **SSH 远端。** 连接前核对目标主机、账号和端口，通过必要的只读检查确认远端系统；
  首次写入前明确任务目录。已确认的信息可以复用；仅能登录服务器不代表获准修改其任意目录。
- **Linux/POSIX 远端。** 直接使用本文件“SSH 远程 Linux 操作”一节及共用的工作流程、
  权限、Git 和停止条件；远程安全规则完整包含在本文件内。
- **文件传输或其他远端系统。** SCP/SFTP 上传时检查远端目标，下载时检查本地目标，
  同步删除分别检查两端。远端为 Windows 时使用其 PowerShell 和 Windows 路径规则，
  不发送 Linux 命令；系统类型未确认时先做只读识别。

## 按需读取参考资料

- 需要创建备份、查询磁盘空间、验证快照或恢复文件时，读取
  [references/powershell-rollback.md](references/powershell-rollback.md)；此文件用于 Windows。
- 涉及 SSH 命令、远程脚本或 SCP/SFTP 传输时，使用本文件内置的远程规则。
- 只读取、查看状态或检索文本时，不创建无关的备份目录。
- 参考代码必须先替换为实际授权路径，再完成路径检查；不要直接对任意目录套用示例。

## 工作流程

1. **确认范围。** 从当前任务确定执行主机、工作区、目标和已有授权；不把整个磁盘、
   服务器根目录或登录用户目录当作默认工作区。
2. **检查路径。** 解析绝对路径，核对目录边界、目标类型、目录联接和符号链接。
3. **判定影响。** 区分只读、新建、覆盖、删除、批量脚本和 Git 丢弃改动操作；检查外部
   副作用，不能只看命令名。
4. **准备回滚。** 在受影响主机的工作区检查可用空间，创建唯一回滚点，保存恢复记录并
   验证备份；本地备份不能自动覆盖远端文件的风险。
5. **执行操作。** 本机使用 PowerShell 的独立参数和明确路径，远端使用已确认的 shell
   与安全引用；命令失败立即停止受影响的操作。
6. **核对结果。** 检查任务结果，报告实际改动、回滚点及仍未验证的限制。

## 启用与权限

- 仅在用户显式点名时启用；`agents/openai.yaml` 中的 `allow_implicit_invocation: false` 控制自动调用策略。
- 本技能是操作流程，不是强制拦截器，也不能关闭宿主确认、扩大沙箱权限或取得管理员权限。
- 已在当前会话明确授权的操作无需重复询问；备份本身不授予执行额外操作的权限。
- 本机只处理用户指定的本地项目工作区；已授权的 SSH 任务另外绑定用户指定的远端工作区。涉及任一工作区外文件、注册表、系统设置、服务、驱动、防火墙或需要提升权限的任务，应报告超出本技能范围；不要自行提权。
- 启用本技能不会自动授权新服务器连接、远程写入或上传。不得因进入 SSH 模式而修改本机或远端的认证、权限、系统服务或安全策略。

## Windows 执行约定

本节及下文标注 Windows 的规则适用于 Windows 执行端；Linux/POSIX 远端使用本文件
“SSH 远程 Linux 操作”一节的路径、命令、回滚与恢复规则。

- 优先使用当前可用的 PowerShell，兼容 Windows PowerShell 5.1 与 PowerShell 7。包含中文的 `.ps1` 需要在 5.1 运行时使用 UTF-8 BOM 或确认其编码可被正确识别。
- 使用明确命令名：`Get-ChildItem`、`Get-Content`、`Copy-Item`、`Move-Item`、`New-Item`、`Remove-Item`。处理已有路径优先使用 `-LiteralPath`；不要把 `rm`、`cp`、`mv` 等别名当作 Bash 命令。
- 不要在 PowerShell 枚举路径后，拼接交给 `cmd /c`、批处理或其他 shell 删除或移动。一个文件操作流程使用同一种 shell，参数按独立参数传递，不使用 `Invoke-Expression`。
- 检索优先 `rg`；不可用时使用 `Get-ChildItem` 和 `Select-String`。Python 优先选择实际存在的 `python` 或 `py -3`，不要假设 `python3` 可用。
- 使用 `$workspaceRoot`、`$targetPath` 等任务变量，不覆盖 `$HOME`、`$env:USERPROFILE`、`$env:CODEX_HOME` 等环境值。
- 修改前设置 `$ErrorActionPreference = 'Stop'`；对 `git.exe`、`tar.exe`、Python 等原生程序立即检查 `$LASTEXITCODE`。`-ErrorAction Stop` 不能替代原生退出码检查。
- 若 Windows 执行策略阻止 `.ps1`，报告限制，不自行运行 `Set-ExecutionPolicy` 或绕过策略；可继续静态校验和其他已允许的检查。
- `Start-Process` 启动非交互后台辅助程序时使用 `-WindowStyle Hidden`；用户需要输入或操作的交互窗口除外。

## Windows 工作区与路径边界

在递归删除、递归移动、覆盖或执行会写文件的脚本前：

1. 确认工作区是用户指定的现有文件系统目录，不使用盘符根目录或整个用户目录作为默认工作区。
2. 将工作区和目标解析为绝对路径；用带目录分隔符的工作区前缀做不区分大小写的边界比较，避免把 `C:\project-old` 误认为在 `C:\project` 内。
3. 拒绝对工作区根目录、备份目录本身及工作区外路径做本技能的删除或覆盖操作。新文件也必须检查其现有父目录。
4. 检查路径祖先、目标及递归操作涉及的子项是否包含符号链接、目录联接、挂载点或其他 `ReparsePoint`。发现后先停止该项操作并说明实际边界尚未确认；不要递归跟随到其他位置。
5. 检查脚本的实际写入位置及副作用。裸 Python、PowerShell 或任意脚本的命令名不能证明其安全；本地文件备份不能回滚远程推送、数据库修改或其他外部副作用。

执行前重新检查目标，避免把较早的路径检查当作永久有效。无法读取的目录、持续写入的文件或无法验证的链接都不能视为“已备份”。

## Windows 回滚点规则

- **删除单个文件或目录。** 默认使用 `Move-Item -LiteralPath` 移入工作区 `.trash`，保留
  相对路径；这不是 Windows 系统回收站。
- **覆盖、原地编辑或截断。** 先复制原件并验证，再修改原文件；不要先移动原件导致编辑
  命令找不到文件。
- **移动到已存在的目标。** 同时备份来源和将被覆盖的目标；没有明确覆盖意图时不使用
  `-Force`。
- **批量修改或会写文件的数据脚本。** 修改前做覆盖所有受影响内容的工作区快照。
- **新建文件或目录。** 记录新建路径；恢复时识别这些新增内容，不能仅把旧文件覆盖回来。

覆盖包括 `Set-Content`、`Out-File`、重定向 `>`、`Copy-Item`/`Move-Item` 覆盖目标，以及脚本中的 `WriteAllText`、`open(..., 'w')`、`shutil.rmtree` 等。

每个回滚点使用 `.trash\<UTC 时间戳-随机后缀>\`，避免并发或同一秒多次操作相互覆盖。记录工作区绝对路径、受影响的相对路径、操作类型和恢复方法；不记录密码、令牌或私钥正文。

单文件备份至少比对长度和 SHA-256。目录备份核对相对路径清单以及文件内容；空目录和隐藏文件也要纳入。复制失败、清单缺失或哈希不一致时，禁止继续破坏性操作。

批量快照应包含隐藏文件和未提交文件，排除 `.trash` 以免自我递归。普通独立 Git 仓库需要包含 `.git`；若 `.git` 是指向外部目录的 worktree 元数据文件，工作区快照只能恢复工作文件，不能声称已备份 Git 元数据。

## Git 操作

以下规则同时适用于 Windows 工作区和 Linux/POSIX 远端工作区；备份在仓库所在主机完成。

- `status`、`log`、`diff`、`show` 可在任务范围内执行。
- `add`、`commit` 需要用户授权，已有明确授权时不重复询问。
- 丢弃改动的 `reset --hard`、`clean`、`checkout -- <path>`、`restore <path>` 必须有针对具体操作的授权及已验证的回滚点。普通分支查看或切换不能仅因命令名相同就判为丢弃文件。
- 不把 `git stash` 或一个提交当作完整文件备份：未跟踪、忽略和尚未纳入仓库的文件可能未被覆盖。
- 在回滚记录中保存原 HEAD 和分支信息；涉及索引时也保存暂存区状态。保留 `.git` 的完整快照或经验证的等效恢复方案。
- `git clean` 先预演，例如 `git clean -nd -e .trash/`，实际执行时保持相同路径范围和排除项。任何 `-x`/`-X` 变体都要单独检查预演结果，不能依赖 `.gitignore` 保护备份。
- 如果预演包含 `.trash`、工作区外内容或回滚点未覆盖的文件，停止清理。需要修改 `.gitignore` 时只追加必要的 `.trash/` 条目，先备份该文件；不要覆盖其他规则。
- 不自动执行 `push`、强制推送或修改远程仓库权限。

## Windows 回收站、磁盘与恢复

- 用 `Get-PSDrive -PSProvider FileSystem` 的 `Free` 或目标卷的可用空间检查备份容量；目录占用大小不等于剩余空间。
- 不依赖预期压缩率判断空间足够。根据待备份内容和校验/恢复临时空间预留余量；空间不足时停止覆盖或删除。
- `.trash` 超过 2GB 或 50 个回滚点时提示用户并列出占用，不自动删除旧备份。不要为了做新备份而静默清理旧备份。
- 恢复前先保护当前内容。优先恢复到空的暂存目录，核对内容后再恢复目标；直接解压覆盖不能移除操作后新增的文件，也不是完整回滚。
- 本示例的文件复制和 tar 快照用于普通项目文件内容恢复，不承诺恢复 NTFS ACL、备用数据流、EFS 或其他特殊文件系统元数据；任务依赖这些属性时使用并验证支持它们的备份方案。

## SSH 远程 Linux 操作

本节适用于已授权的 Linux/POSIX 服务器任务。直接使用以下规则执行文件管理、数据处理、
项目脚本、Git 和文件传输；远端不需要安装本技能。远端为 Windows 时使用本文件的
Windows 规则，系统或 shell 未确认时先做只读识别。

### 连接与远端工作区

1. **绑定连接。** 确认 SSH 别名或主机、账号、端口及必要的跳板，复用当前会话已确认的
   信息。换主机、换账号或重新连接后复核实际目标，不额外连接未授权主机。
2. **确认环境。** 通过最小只读检查确认远端系统、当前用户、shell 和工作目录；登录
   成功不代表获得对服务器任意目录的修改授权。
3. **限定工作区。** 使用用户指定的远端任务目录。目录未明确时先确认，可以继续必要的
   只读诊断；不得把 `/`、整个 home 或服务器全部项目作为默认范围。
4. **核对路径。** 在远端解析工作区和目标的规范绝对路径，新目标检查现有父目录。按
   POSIX 目录边界区分大小写，避免把 `/work/app-old` 当作 `/work/app` 内部路径。
   检查祖先、目标、递归子项的符号链接及挂载点；边界无法确认时停止写入，不递归跟随。
5. **保护边界。** 不删除或覆盖工作区根目录、回滚目录本身及工作区外内容。写入前复核
   目标，检查脚本实际写入位置和外部副作用，不以命令白名单代替检查。

仅在已授权工作区内执行无需提权的任务。`sudo`、系统级修改（如 `apt`、`systemctl`、
`reboot`）、对 `/etc`、`/usr`、`/opt`、`/var` 的写入，以及 `dd`、`mkfs` 不属于本技能
范围；需要时停止并报告，备份不能豁免这些限制。

保留 SSH 主机身份校验。首次连接或主机密钥变化时通过可信渠道核验，不使用
`StrictHostKeyChecking=no`，不把 known_hosts 指向 `NUL` 或 `/dev/null` 绕过检查。
优先复用已配置的密钥或 SSH agent；不将密码、令牌、私钥正文写进命令、脚本、日志、
回滚记录或报告，不为方便而修改服务器的 SSH 安全设置。

### Linux 命令与回滚点

- **常规操作。** 使用远端实际可用的 `cp`、`mv`、`mkdir`、`python3`、项目脚本和
  Git 命令。即使是普通文件命令或 Python，也先检查是否覆盖、删除或写入工作区外。
- **删除。** 默认移入远端工作区 `.trash/<UTC 时间戳-随机后缀>/` 并保留相对路径。
  `rm`、`rmdir`、`unlink`、`shred`、`find -delete` 和脚本内部删除都属于破坏性操作，
  不能绕过回滚点要求。
- **覆盖或截断。** 对 `>`、`truncate`、`sed -i`、复制覆盖及脚本的 `open(..., 'w')`
  等写入，先复制并验证原内容，再修改原文件；不要先移走原件使后续编辑失去输入。
- **移动覆盖。** 同时保护来源和将被覆盖的目标，记录两者位置；无明确覆盖意图时不
  强制覆盖目标。
- **批量或高危操作。** 执行批量覆盖、会写文件的数据脚本或破坏性 Git 操作前，在
  远端创建工作区快照。包含所有受影响的文件、空目录、隐藏内容、未跟踪和忽略文件，
  排除 `.trash` 以免自我递归；不能仅因数据目录较大就排除将被修改的内容。
- **Git 状态。** 遵循本文件共用的 Git 规则，保存 HEAD、分支和涉及的索引状态；独立
  仓库快照包含 `.git`。worktree 外部元数据未备份时明确限制，不能声称可完整恢复 Git。
- **新建内容。** 记录新建文件和目录，恢复时单独处理；只覆盖旧文件不能完成回滚。

创建归档前先创建唯一备份目录。使用远端 `df -Pk -- "$remote_workspace"` 或目标
文件系统的等效只读查询检查可用空间；`du` 只统计占用，本机磁盘余量不能代替远端余量。
按待备份内容及校验、恢复临时空间预留余量，不依赖预期压缩率；空间不足时停止破坏性
操作。远端 `.trash` 超过 2GB 或 50 个回滚点时提示并给出检查、手动清理方法，不自动
清理旧备份。

备份与验证均在受影响的远端完成。记录主机、账号、工作区绝对路径、受影响的相对路径、
操作类型、原状态和恢复方法。单文件至少比对长度和 SHA-256；目录核对路径清单、文件
内容以及空目录、隐藏文件。仅列出归档成员或计算归档自身哈希不足以证明源内容已完整
备份；高危操作前还需比对源文件清单及内容，或在空暂存目录试恢复并与源内容核对。
读取失败、文件持续变化、复制失败或校验不一致时停止，不声称备份已完成。

### SSH 命令与脚本传递

- 区分 PowerShell 本地解析和远端 shell 解析。SSH 命令最终由远端 shell 解释，本地
  分开传递参数不能自动解决远端引用问题。
- 不将未经验证的主机、路径、文件名或用户文本直接拼成远端命令。正确处理空格、
  单引号、美元符号、反引号、分号和前导连字符，使用适合远端 shell 的引用和选项边界；
  不确定时使用经过审阅的脚本与结构化输入，避免多层拼接。
- PowerShell 中包含远端 `$HOME` 或 `$remote_workspace` 的脚本文本使用不展开变量
  的单引号字符串或单引号 here-string，避免提前替换为本机值。
- 向 Linux 传递脚本时使用 UTF-8 无 BOM、LF 行尾，检查实际传输字节；不依赖 Windows
  PowerShell 5.1 默认文本管道的编码。临时脚本仅放在已授权远端工作区，保护同名旧
  文件，传输校验后才执行。
- 非交互命令可用 `ssh -T`，需要口令的交互流程单独处理。远端脚本显式检查关键命令
  的结果，失败返回非零退出码，不让后续成功命令掩盖失败。
- 本机立即检查 `ssh.exe`、`scp.exe` 等原生程序的 `$LASTEXITCODE`。连接中断或超时
  可能发生在部分写入之后，先只读核实状态，再决定后续动作；不盲目重试删除、移动
  或覆盖。

### SCP、SFTP 与同步

- **上传。** 远端目标已存在时先在远端备份并验证，再传输并核对目标大小与哈希。
  备份本地源文件不能保护远端旧文件。
- **下载。** 按 Windows 规则保护已有本地目标，再接收并校验；远端仅作为读取来源
  时不创建无关的远端备份。
- **同步。** 明确方向和删除选项，预览受影响路径。`rsync --delete` 或镜像、清理选项
  按删除操作处理；两端中实际会被修改的目标分别需要授权与回滚点，并排除 `.trash`。
- **跨端移动。** 先完整传输并验证接收端，再按来源端规则处理删除；部分上传成功
  不能作为丢弃源文件的依据。

### 远端恢复

恢复前确认同一服务器、账号和工作区，先保护当前状态。解包前检查归档成员，拒绝绝对
路径、`..` 越界成员及未确认链接；将备份恢复到空暂存目录并校验，再逐项恢复目标。
单独处理操作后新增的文件，不能把直接覆盖解压视为完整回滚。

普通文件复制或 tar 不保证保留 ACL、扩展属性、所有权及其他特殊元数据；任务依赖这些
属性时，使用并验证相应备份选项与恢复权限。本地备份不能代替远端回滚点，文件快照也
不能回滚推送、数据库修改或其他外部副作用。

## 质量门槛与停止条件

目标越界、路径解析不明、需要提权、备份或校验失败、磁盘不足、未明确授权丢弃数据时，停止受影响的操作并说明原因；可以继续无关的只读检查。

用户说“可以删”仍默认送入相应主机工作区的 `.trash`。点名 `Remove-Item` 或 `rm` 不自动豁免备份；用户另外明确要求不保留副本时，按其具体授权及宿主权限规则处理，不把它扩大为其他删除许可。

## 完成时报告

报告实际改动、回滚点的绝对路径、验证结果和恢复方法，以及未覆盖的文件系统属性、未完成
的检查或需要用户处理的权限边界。没有实际验证就不要声称一定可以回滚。

涉及远程任务时，同时标明远端主机、账号、端口、工作区和远端回滚点路径；区分本机与
远端结果，并说明 SSH 中断后是否已核实操作状态。
