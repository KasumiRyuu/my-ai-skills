# SSH 远程操作约束

涉及 SSH 命令、远程脚本、SCP、SFTP 或 rsync 时读取本文件。远端 Linux/POSIX 的路径、
回滚、Git、恢复和停止条件遵循 [SKILL.md](../SKILL.md)；本文件补充连接及跨端操作要求。

## 连接与远端工作区

1. **绑定连接。** 确认 SSH 别名或主机、账号、端口及必要跳板，复用当前会话已确认的
   信息；换主机、换账号或重新连接后复核实际目标，不额外连接未授权主机。
2. **确认环境。** 以最小只读检查确认实际系统、当前用户、执行命令的 shell 和工作目录。
   登录成功不代表获得对任意目录的写入授权；环境未确认时不发送平台专用的写入命令。
3. **限定目录。** 使用用户指定的远端任务目录；目录未明确时先确认，可以继续必要的
   只读诊断。不把 `/`、整个 home 或服务器全部项目作为默认范围。
4. **逐次定位。** 每条独立 SSH 命令或脚本显式定位到已核对的绝对工作区，检查 `cd`
   成功后才继续；上一次连接中的目录和变量不会自动保留。交互会话写入前也要复核。
5. **在远端检查。** 路径规范化、符号链接及挂载点检查在实际执行端进行，遵守主文件的
   目录边界；不要用本机的同名目录、环境变量或路径解析结果代替远端检查。

仅在已授权工作区内执行无需提权的操作。即使账号具备管理员能力，也不改变任务范围；
不得为连接或写入方便而修改认证、系统权限、SSH 服务或安全策略。

## 主机身份与认证

- 保留 SSH 主机身份校验。首次连接或主机密钥变化时通过可信渠道核验指纹；不能核实
  时停止连接，不使用 `StrictHostKeyChecking=no`/`off`、丢弃 known_hosts 或删除旧记录
  来绕过身份冲突。相关选项参见 [OpenSSH 配置手册](https://man.openbsd.org/ssh_config.5)。
- 复用已配置的密钥或 SSH agent。不将密码、令牌、私钥正文写入命令、脚本、日志、
  回滚记录或报告，也不为完成普通任务复制私钥到服务器。
- SSH 登录授权不自动包含 agent 转发、端口转发或继续从远端连接其他主机；只有任务
  明确需要且已授权时才启用相应能力。

## 命令与脚本传递

- 区分本机 shell 解析和远端 shell 解析；OpenSSH 会把远端命令参数用空格拼成命令文本，
  本机分开传参不能自动保留远端参数边界。参见 [OpenSSH 命令手册](https://man.openbsd.org/ssh.1)。
- 不将未经验证的主机、路径、文件名或用户文本直接拼入命令。正确处理空格、单引号、
  美元符号、反引号、分号和前导连字符；采用适合实际 shell 的引用和选项边界，不使用
  `eval` 重新解释输入。不确定时使用经审阅的固定脚本与结构化输入，避免多层拼接。
- 本机为 POSIX shell 时，包含远端变量的脚本文本使用适当的单引号或带引号分隔符的
  here-document；不要让 `$HOME`、`$remote_workspace` 或命令替换在本机提前展开。
  本机为 PowerShell 时用单引号字符串或单引号 here-string 保留远端文本。
- 确认远端实际 shell；需要 Bash 特性时先确认 Bash 可用并显式选择，不假设 `/bin/sh`
  支持 Bash 语法。传给 Linux 的脚本使用 UTF-8 无 BOM、LF 行尾并核对实际字节，不依赖
  Windows PowerShell 5.1 默认文本管道编码。
- 临时脚本及输入仅放入已授权远端工作区，使用唯一名称；若会覆盖同名内容，先在远端
  备份。落盘传输后校验内容再执行，脚本清理同样遵守删除规则。
- 非交互命令可用 `ssh -T`；需要用户输入的认证单独处理，不把口令混入脚本标准输入。
  显式检查远端 `cd`、备份、校验和写入等关键步骤，失败返回非零状态，不依赖单独的
  `set -e` 保证整个流程成功。

## 远端回滚点与恢复

- 覆盖、删除或批量修改前，在远端工作区建立并验证 `.trash/<UTC 时间戳-随机后缀>/`
  回滚点；本机源文件或下载副本不能自动代替远端原状态。
- 在远端目标文件系统检查可用空间，包含验证和恢复所需余量；本机磁盘余量或 `du`
  统计不能替代该检查。远端 `.trash` 达到主文件阈值时提示，不自动清理。
- 记录实际主机、账号、端口、工作区和回滚点绝对路径，以及受影响的相对路径、原状态
  与恢复方法。适用时保存 HEAD、分支及暂存区状态，遵守主文件对 Git 元数据的限制。
- 恢复前重新核对同一服务器、账号及工作区，先保护当前内容；按主文件在空暂存目录
  验证归档并处理新增路径，不直接解压覆盖。需要特殊属性或权限时先验证恢复能力。

## SCP、SFTP 与 rsync

- **传输前。** 确认方向、两端绝对路径及所用客户端的路径语义，检查实际来源和目标。
  SCP/SFTP 与远端 shell 的引用方式不能混用，通配符或递归传输需先核对匹配范围；
  目录尾随 `/` 等语义会影响落点，不能凭命令外观推断目标。
- **上传。** 远端目标已存在时先在远端备份并验证，再传输并核对接收内容的大小和哈希；
  批量传输核对路径清单、空目录与文件内容。备份本地源文件不能保护远端旧文件。
- **下载。** 在本地目标主机按其系统规则保护已有内容，再接收并校验；远端只作为读取
  来源时不创建无关的远端备份。Windows 本地目标使用 PowerShell 与 Windows 路径规则。
- **同步。** 明确源、目标、覆盖和删除选项，使用 `rsync --dry-run --itemize-changes`
  或等效预览检查受影响路径；实际执行保持相同范围和过滤规则。`--delete`、镜像和
  清理选项按删除处理，即使未启用删除也需保护将被覆盖的目标。
- **保护备份。** 同步时排除来源的 `.trash` 并保护接收端的 `.trash` 不被删除或覆盖。
  `--delete-excluded` 会改变普通排除规则的删除保护，不能只加 `--exclude=.trash/`
  就认为安全；采用经过预览验证的接收端保护规则，否则停止该项同步。参见
  [rsync 手册的过滤与删除规则](https://download.samba.org/pub/rsync/rsync.1)。
- **跨端移动。** 先完整传输并验证接收端，再按来源端规则处理删除。两端实际被修改的
  内容分别需要授权和回滚点；部分传输成功不能作为丢弃源文件的依据。

## 退出状态与连接中断

- 本机及时检查 `ssh`、`scp`、`sftp` 或 `rsync` 的退出状态；POSIX shell 检查 `$?`
  或直接按命令成功与否分支，PowerShell 检查 `$LASTEXITCODE`。交互会话或后台任务还需
  检查具体命令及实际产物，客户端正常退出不代表每项操作成功。
- 超时或断线可能发生在部分写入之后，远端进程也可能继续运行。将状态标为待核实，
  不盲目重试覆盖、移动、删除或整个批量脚本，也不在写入仍进行时直接回滚。
- 重新连接后先只读核对主机、账号、目录、相关进程、受影响文件、Git 状态和回滚记录；
  确认已完成范围、剩余动作及备份有效性后，在原授权范围内继续或恢复。无法确认时
  停止写入并报告，不能把连接失败当作“没有发生修改”。
