# Linux 自主安全操作（Safe Autonomous Ops）

## 核心目标与执行位置

在已授权的 Linux/POSIX 项目工作区内自主完成常规操作，在覆盖或丢弃原内容前建立并
验证回滚点。本文件的路径、命令、Git 和恢复规则同时适用于 Linux/POSIX 本机和远端。

- **本机操作。** 使用用户指定的本地项目目录，不把 `/` 或整个 home 作为默认工作区。
- **SSH 远端操作。** 先读取 [SSH 远程操作约束](references/ssh-remote-operations.md)，
  将任务绑定到已授权的主机、账号、端口和远端目录，再按本文件执行。远端无需安装本技能。
- **文件传输。** 涉及 SCP、SFTP 或 rsync 时同样读取该参考文件；两端分别检查授权、
  路径和回滚点。本机备份不能代替远端备份，反之亦然。
- **其他系统。** 系统或 shell 未确认时先只读识别。Windows 执行端需使用其原生路径、
  命令与回滚流程；不要向 Windows 远端套用本文件的 POSIX 命令。

## 启用与权限

- 仅在用户显式点名时启用；`agents/openai.yaml` 中的
  `allow_implicit_invocation: false` 控制自动调用策略。
- 本技能是操作流程，不能关闭宿主确认、扩大沙箱权限或取得管理员权限。不要用宽泛的
  命令前缀放行替代操作检查；`cp`、`mv`、`tar`、Python 和 SSH 都可能产生破坏性影响。
- 当前会话已明确授权的操作无需重复询问。备份不授予额外权限，启用本技能也不自动
  授权新服务器连接、上传、远端写入或 Git 推送。
- 仅处理已授权工作区内无需提权的任务。`sudo`、系统级修改（如 `apt`、`systemctl`、
  `reboot`）、对 `/etc`、`/usr`、`/opt`、`/var` 的写入及 `dd`、`mkfs` 不在本技能范围内；
  需要时停止并报告，不自行提权，备份不能豁免这些限制。

## 工作流程与路径边界

1. **确认范围。** 明确操作实际发生的主机、工作区、目标与已有授权。只读检索或状态
   检查不创建无关的备份目录。
2. **解析路径。** 在执行端解析工作区和目标的规范绝对路径，新目标检查现有父目录。
   按 POSIX 目录边界区分大小写，避免把 `/work/app-old` 当作 `/work/app` 内部路径。
3. **检查链接。** 检查路径祖先、目标和递归子项中的符号链接及挂载点；实际边界未确认
   时停止该项写入，不递归跟随到其他位置。
4. **限制影响。** 不删除或覆盖工作区根目录、回滚目录本身及工作区外内容。审阅脚本的
   实际写入位置和外部副作用，不以裸 `python3` 或其他命令名判断安全。
5. **准备回滚。** 在受影响主机检查磁盘空间，创建唯一回滚点，保存恢复记录并验证。
   写入前重新核对目标，较早的路径检查不永久有效。
6. **执行并核对。** 使用执行端实际可用的工具与已确认的 shell；变量正确引用，支持
   时使用 `--` 分隔选项与路径。显式检查关键命令退出状态，失败停止受影响的操作，
   不让后续成功命令掩盖失败。完成后检查实际内容和任务结果。

## 回滚点规则

- **删除。** 默认移入执行端工作区 `.trash/<UTC 时间戳-随机后缀>/`，保留原相对路径，
  不覆盖已有备份。`rm`、`rmdir`、`unlink`、`shred`、`find -delete`、`rsync --delete`
  及脚本内部删除都属于破坏性操作，不能绕过回滚要求。
- **覆盖、原地编辑或截断。** 先复制原件并验证，再修改原文件；不要先移走原件导致
  编辑命令找不到输入。包括 `>`、`truncate`、`sed -i`、复制覆盖及 `open(..., 'w')`。
- **移动到已存在的目标。** 同时保护来源和将被覆盖的目标，记录两者位置；没有明确
  覆盖意图时不强制覆盖。
- **批量或高危操作。** 批量覆盖、会写文件的数据脚本及丢弃改动的 Git 操作前，创建
  工作区快照。包含受影响的文件、空目录、隐藏内容、未跟踪和忽略文件，排除 `.trash`
  以免自我递归；不能仅因数据目录较大就排除将被修改的内容。
- **新建内容。** 记录新建文件和目录，恢复时单独处理；仅覆盖旧文件不能完成回滚。

先创建唯一备份目录，再复制或归档。记录执行主机、工作区绝对路径、受影响的相对路径、
操作类型、原状态和恢复方法；不记录密码、令牌或私钥正文。

单文件至少比对长度和 SHA-256；目录核对相对路径清单和文件内容，包含空目录及隐藏文件。
仅列出归档成员或计算归档自身哈希不能证明源内容已完整备份；快照还需与源文件清单和
内容核对，或在空暂存目录试恢复后与源内容比对。读取失败、文件持续变化、复制失败或
校验不一致时停止，不声称回滚点已验证。

## 磁盘空间与备份保留

- 在实际存放回滚点的主机和文件系统上用 `df -Pk` 或等效只读查询检查可用空间；`du`
  只统计占用，不能证明剩余空间足够。按待备份内容和校验、恢复临时空间预留余量，
  不依赖预期压缩率。
- `.trash` 超过 2GB 或 50 个回滚点时提示用户并列出占用，给出检查及手动清理方法；
  不自动清理旧备份，也不为腾出空间而静默删除。
- Git 项目中新建备份应由 `.gitignore` 排除；需要时先备份该文件，只追加必要的
  `.trash/` 条目，保留其他规则。忽略规则不能保护已跟踪的备份，提交前核对暂存范围。

## Git 操作

- `status`、`log`、`diff`、`show` 可在任务范围内执行。`add`、`commit` 需要用户授权，
  已明确授权时不重复询问。
- 丢弃改动的 `reset --hard`、`clean`、`checkout -- <path>`、`restore <path>` 需要
  针对具体操作的授权及已验证的回滚点；普通分支查看或切换不因命令名相同就视为丢弃。
- 不把 `git stash` 或一个提交当作完整文件备份：未跟踪、忽略文件可能未被覆盖。
- 回滚记录保存原 HEAD、分支及涉及的暂存区状态；独立仓库快照包含 `.git`。若 `.git`
  是指向工作区外元数据的文件（如 worktree 或子模块），不得擅自扩大备份范围；没有
  已授权且验证过的等效恢复方案时，不声称可完整恢复 Git，不执行依赖该能力的破坏性操作。
- `git clean` 先预演，例如 `git clean -nd -e .trash/`；实际执行保持相同路径范围和
  排除项。`-x`/`-X` 变体须单独检查预演，不能依赖 `.gitignore` 保护备份。预演包含
  `.trash`、工作区外内容或回滚点未覆盖的文件时停止。
- 仅在用户明确授权后推送；普通推送授权不包含强制推送或修改远程仓库权限。文件快照
  不能撤销远程推送等外部副作用，推送前核对目标远程、分支和提交范围。

## 恢复

1. 核对回滚记录对应的主机、工作区和目标边界，验证备份，先保护当前内容。
2. 单文件核对原相对路径后恢复；归档解包前检查成员，拒绝绝对路径、`..` 越界成员及
   未确认链接。将归档恢复到空暂存目录并校验，再逐项恢复目标。
3. 单独处理操作后新增的文件和目录；直接向工作区解压覆盖不能视为完整回滚。恢复 Git
   元数据前确认没有进程占用并核对恢复方案，完成后检查内容和 Git 状态。

普通文件复制或 tar 不保证保留 ACL、扩展属性、所有权等特殊元数据；任务依赖这些属性
时使用并验证相应备份方案与恢复权限。文件快照不能回滚数据库修改或其他外部副作用。

## 停止条件与完成报告

目标越界、路径解析不明、需要提权、备份或校验失败、磁盘不足、未明确授权丢弃数据时，
停止受影响的操作并说明原因；可以继续无关的只读检查。

用户说“可以删”仍默认送入相应主机工作区的 `.trash`。点名 `rm` 不自动豁免备份；用户
另外明确要求不保留副本时，按其具体授权及宿主权限规则处理，不扩大为其他删除许可。

完成时报告实际改动、回滚点绝对路径、验证结果和恢复方法，以及未覆盖的属性和未完成
的检查。涉及远端时标明主机、账号、端口、工作区，区分本机与远端结果；连接中断后的
操作状态未核实前不得报告成功。
